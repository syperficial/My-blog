🚀 接口响应慢的优化方案：缓存 + 异步刷新 ​

🌐 目标：页面秒开，数据渐进更新 ​

核心思想： ​

  • ✅ 页面初始展示上次缓存数据 →
  • ✅ 后台异步刷新最新数据 →
  • ✅ 成功后更新视图并写入缓存 →
  • ✅ 即便接口挂了也不影响用户体验

🏗️ 实现一：Pinia 本地缓存 Store 封装 ​

📦 示例：likeStore 封装（支持多 tab 缓存）

js
// stores/like.js
import { defineStore } from 'pinia'
import { ref } from 'vue'

export const useLikeStore = defineStore('like', () => {
  const likeList = ref({}) // 使用对象支持多 key 缓存（如 tab 状态）

  // 设置缓存数据
  const setLikeList = (key, list) => {
    likeList.value[key] = list
  }

  // 获取缓存数据
  const getLikeList = (key) => {
    return likeList.value[key] || []
  }

  // 清空所有缓存
  const clearLikeList = () => {
    likeList.value = {}
  }

  return {
    likeList,
    setLikeList,
    getLikeList,
    clearLikeList
  }
}, {
  persist: true // 持久化缓存（localStorage）
})

🧩 实现二：组件中使用缓存 + 异步拉取数据 ​

js
import { useLikeStore } from '@/stores/like'
const likeStore = useLikeStore()
const orderList = ref([])

// 请求参数
const params = ref({
  orderState: 1 // 当前 tab 类型
})

✅ 初始化加载：缓存优先 + 异步刷新 ​

js
const loadCache = () => {
  orderList.value = likeStore.getLikeList(params.value.orderState)
}

const getOrderList = async () => {
  try {
    const res = await GetMyOrder(params.value)
    orderList.value = res.result.items

    // 同步更新缓存
    likeStore.setLikeList(params.value.orderState, res.result.items)
  } catch (error) {
    console.warn('接口请求失败，保留旧数据', error)
  }
}

// 页面首次加载
loadCache()
getOrderList()

🔁 实现三：Tab 切换时防止数据串台（缓存污染） ​

js
const tabChange = (type) => {
  params.value.orderState = type
  loadCache()      // 使用当前 tab 的旧数据
  getOrderList()   // 后台拉取最新数据
}

📦 特别提示 ​

  • 适用场景：
    • 商品列表、订单管理、搜索历史、热榜、文章详情页等一切“允许展示旧数据”的模块
  • 设计原则：
    • ❗ 旧数据不要删除，让页面“立即渲染”
    • ✅ 后台刷新要能失败兜底（不影响页面结构）
    • 💾 数据要区分 key 保存，防止多个 tab 共用同一份数据
