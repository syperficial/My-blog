Vue 面试知识点整理 ​

📌 MVVM 的理解 ​

MVVM 是一种软件架构模式，全称为 Model-View-ViewModel，其核心思想是将视图（View）与业务逻辑（Model）进行解耦：

  • Model：代表数据模型，负责存储和处理业务数据；
  • View：即用户界面，负责将数据展示给用户；
  • ViewModel：连接 Model 和 View，负责双向绑定，监听数据变化并更新视图，同时接收视图的交互更新 Model。

✅ 特点：Model 与 View 无直接联系，而是通过 ViewModel 完成双向绑定。

🧭 SPA（单页应用）详解 ​

🧠 什么是 SPA？ ​

SPA（Single Page Application，单页应用）是一种 Web 应用程序架构模式。其核心特征是：

在初次加载时，仅加载一次 HTML、CSS、JavaScript 等资源，后续页面的切换与更新通过 JavaScript 动态处理，无需重新加载整个页面，从而实现无刷新的用户体验。

⚖️ SPA 与多页面应用（MPA）的对比 ​

维度SPA（单页应用）MPA（多页应用）
页面加载方式初始加载单个 HTML，后续通过 JS 动态更新内容每个页面是独立 HTML，切换时需重新加载页面
用户体验页面切换流畅，无需刷新页面切换伴随刷新，有白屏
组件复用支持组件化开发，复用度高页面独立，组件复用较低
路由管理前端路由（如 Vue Router、React Router）服务端路由，每个 URL 对应一个 HTML 页面
SEO 优化依赖前端渲染，不利于 SEO，需要 SSR/预渲染等优化HTML 页面可直接被搜索引擎爬取，SEO 友好
服务端压力降低服务端负载，更多逻辑由前端承担每次跳转都需向服务端请求整个页面，服务端压力较大

🌟 SPA 的优点 ​

  • ✅ 用户体验优秀：页面无刷新切换，操作流畅。
  • ✅ 组件化开发：利于模块复用，提高维护效率。
  • ✅ 服务器负载小：前端动态更新，减少重复请求。
  • ✅ 前后端分离：通过 API 通信，实现更清晰的职责划分。
  • ✅ 实时交互性强：依赖 Ajax、Axios 实现动态数据刷新。

⚠️ SPA 的缺点 ​

  • ❌ 首屏加载慢：初次加载需要拉取大量 JS、CSS 文件，首屏渲染时间长。
  • ❌ SEO 问题：搜索引擎对动态内容抓取能力有限，需 SSR 或预渲染处理。
  • ❌ 内存占用高：由于页面长时间驻留内存，状态管理不当可能导致内存泄漏。
  • ❌ 安全性挑战：大量通过 API 通信，需要加强认证、授权、安全防护。

🚀vue 的性能优化有哪些 ​

🧩 编码阶段 ​

  • 🔍 避免 v-if 和 v-for 同时使用
    Vue 的编译器会优先处理 v-for，再处理 v-if，这会导致每次遍历都进行条件判断，浪费性能。

  • 🧩 确保 v-for 使用唯一的 key
    利于虚拟 DOM 的 Diff 算法更高效地识别变更，避免组件重复渲染。

  • 🧠 使用 keep-alive 缓存组件
    对于需要频繁切换的页面（如 Tab 页），使用 <keep-alive> 包裹组件可缓存状态，避免重复渲染。

  • 🎯 根据场景选择 v-if 与 v-show

    • v-if 更适合条件少且不常切换的组件；
    • v-show 更适合频繁切换显示的组件。

  • 📦 路由懒加载 / 异步组件
    使用动态 import()，将路由组件拆分为独立 chunk，减少首屏体积。

  • 🕓 函数节流与防抖

    • 节流（throttle）：限制函数在单位时间内只执行一次；
    • 防抖（debounce）：延迟函数执行，防止频繁触发。

  • 🧱 第三方库按需引入
    例如：使用 babel-plugin-import 引入 Element Plus、Lodash 等库时只引入所需模块。

  • ⚙️ 使用服务端渲染（SSR）
    Vue SSR（如 Nuxt.js）提升首屏加载速度，对 SEO 更友好。

📦 打包构建阶段优化 ​

  • 🧨 压缩 JavaScript/CSS/HTML
    使用 vite 或 webpack 内置的压缩插件（如 terser、esbuild）减少资源体积。

  • 🌐 使用 CDN 加载第三方库
    将大型依赖（如 Vue、axios、echarts）通过 <script src> 从 CDN 引入，减轻主包负担。

  • 🗂 抽离公共依赖文件
    使用 splitChunks 机制（webpack）或 Rollup 的 manualChunks 将共享代码单独打包。

🎨 提升用户体验 ​

  • 🦴 使用骨架屏（Skeleton）
    在数据加载前提供页面占位，减少白屏时间，提升感官体验。

  • 🗃 客户端缓存机制
    结合 localStorage、sessionStorage、IndexedDB、HTTP 缓存头（如 ETag）等，减少重复请求。

🌐 SEO 相关优化 ​

  • 📄 预渲染（Pre-rendering）
    使用 vite-plugin-ssr 或 prerender-spa-plugin 在构建阶段生成静态 HTML，适合中小项目。

  • 🔁 服务端渲染（SSR）
    使用 Nuxt、Express + Vue SSR 等方案，实现服务端页面直接返回 HTML 内容。

  • 📑 合理使用 meta 标签
    提供 title、description、keywords 等信息，提高搜索引擎爬虫识别能力。

常用的属性，指令有哪些 ​

属性 ​

  • data： 用于定义组件的初始化数据。
  • props： 用于传递数据给子组件
  • computed： 用于定义计算属性
  • methods： 用于定义组件方法
  • watch： 用于监听组件的数据变化
  • components： 用于注册子组件，可以通过 components 属性将其他组件注册为当前组件的子组件从而在模板中使用这些子组件

指令 ​

  • v-if：根据表达式条件动态地销毁或创建元素。
  • v-show：根据条件切换元素的可见性 (display: none)。
  • v-for：基于数组或对象的列表进行渲染。
  • v-bind：动态绑定 HTML 属性或组件 prop。
  • v-on：绑定事件监听器。
  • v-model：双向绑定表单数据。
  • v-text：更新元素的 textContent。
  • v-html：更新元素的 innerHTML（有 XSS 风险）。
  • v-cloak：防止闪烁，直到 Vue 编译结束。
  • v-once：只渲染一次，后续数据变更不再更新该节点。

Computed 和 Watch 的区别 ​

Computed(计算属性)

  • 通过对自己已有的属性进行一个计算得到一个新值，它需要依赖于其他的数据 当数据发生变化时， computed 会自动计算更新
  • computed` 属性值 会被缓存，只有当依赖数据发生变化才会重新计算 避免重复计算 提高性能

Watch（监听）

  • 用于监听数据的变化 ，并在变化时执行一些操作，他可以监听单个数据或数组，当数据发生变化时会执行对应的回调函数，和 computed 不同的是 watch 不具备缓存功能

路由 hash 和 histore 模式的区别 ​

hash 模式 开发中默认的模式，地址栏 URL 后携带#，后面为路由。 原理是通过onhashchange()事件监听hash值变化，在页面hash值发生变化后，window就可以监听到事件改变，并按照规则加载相应的代码。hash值变化对应的 URL 都会被记录下来，这样就能实现浏览器历史页面前进后退。

history 模式history模式中 URL 没有#，这样相对hash模式更好看，但是需要后台配置支持。 history原理是使用HTML5 history提供的pushState、replaceState两个 API，用于浏览器记录历史浏览栈，并且在修改 URL 时不会触发页面刷新和后台数据请求。

router 和 route 的区别 ​

  • ·$route 是路由信息，包括path、params、query、name`等路由信息参数
  • ·$router` 是路由实例，包含了路由跳转方法、钩子函数等

如何设置动态路由 ​

params传参

-路由配置： /index/:id - 路由跳转：this.$router.push({name: 'index', params: {id: "zs"}}); - 路由参数获取：$route.params.id - 最后形成的路由：/index/zs

query传参

-路由配置：/index正常的路由配置 - 路由跳转：this.$rouetr.push({path: 'index', query:{id: "zs"}}); - 路由参数获取：$route.query.id - 最后形成的路由：/index?id=zs

区别

  • 获取参数方式不一样，一个通过$route.params，一个通过 $route.query
  • 参数的生命周期不一样，query参数在 URL 地址栏中显示不容易丢失，params参数不会在地址栏显示，刷新后会消失

路由守卫 ​

  • 全局前置钩子：beforeEach、beforeResolve、afterEach
  • 路由独享守卫：beforeEnter
  • 组件内钩子：beforeRouterEnter、beforeRouterUpdate、beforeRouterLeave

Vue 中 key 的作用 ​

key的作用主要是为了高效的更新虚拟DOM，其原理是vue在patch过程中通过key可以精准判断两个节点是否是同一个，从而避免频繁更新不同元素，减少DOM操作量，提高性能。

为什么不建议用 index 作为 key? ​

如果将数组下标作为key值，那么当列表发生变化时，可能会导致key值发生改变，从而引发不必要的组件重新渲染，甚至会导致性能问题。例如，当删除列表中某个元素时，其后面的所有元素的下标都会发生改变，导致Vue重新渲染整个列表。

为什么 v-for 和 v-if 不能一起使用 ​

v-for比v-if优先级更高，一起使用的话每次渲染列表时都要执行一次条件判断，造成不必要的计算，影响性能。

原理知识 ​

双向数据绑定的原理 ​

Vue 的双向绑定本质上是：数据劫持 + 发布订阅模式 的组合。

  1. 初始化阶段，Vue 会实例化一个 Observer 对象，对 data 中的数据进行递归劫持。
  2. 使用 Object.defineProperty() 拦截每一个属性的读取和修改，分别添加 getter 和 setter：
    • getter： 用于依赖收集，把使用到该数据的 Watcher 添加进依赖列表。
    • setter： 在数据变动时触发，对所有依赖 Watcher 发送通知，触发视图更新。
  3. 页面上每一个使用该数据的地方，都会被一个 Watcher 实例所关联，Watcher 接收到通知后，调用 update() 方法重新渲染对应视图。

使用 Object.defineProperty() 来进行数据劫持有什么缺点？ ​

  • 1.无法监听对象属性的新增或删除
  • 2.无法直接监听数组的索引变化
  • 3. 需对数组方法进行手动处理

和Vue3相比有什么区别？ ​

Vue3采用了 proxy代理的方式，它提供了一个用于创建代理对象的构造函数

  • 可以对对象所有操作进行处理 而 Object.defineProperty 只能监听单个属性 不能增删改查

Vue是如何收集依赖的？ ​

依赖收集发生在defineReactive()方法中，在方法内new Dep()实例化一个Dep()实例，然后在getter中通过dep.depend()方法对数据依赖进行收集，然后在settter中通过dep.notify()通知更新。在收集数据依赖的时候，会为数据创建一个Watcher，当数据发生改变通知每个Watcher，由Wathcer进行更新渲染。

slot是什么？有什么作用？原理是什么？ ​

slot插槽，一般在封装组件的时候使用，在组件内不知道以那种形式来展示内容时，可以用slot来占据位置，最终展示形式由父组件以内容形式传递过来，主要分为三种：

1. 默认插槽（匿名插槽） ​

  • 不带 name 属性的 slot；
  • 一个组件中只能有一个默认插槽；
  • 父组件传入的内容会被插入到 slot 标签所在位置。

2. 具名插槽（Named Slot） ​

  • 使用 name 属性标记插槽；
  • 允许在一个组件中定义多个插槽；
  • 父组件通过 v-slot:name（或旧语法 slot="name"）指定插入目标。

3. 作用域插槽（Scoped Slot） ​

  • 子组件通过插槽向父组件传递数据；
  • 父组件可以根据传来的数据决定渲染内容；
  • 本质是一个函数插槽（接收 slot props）。
  • 实现原理： 当子组件vm实例化时，获取到父组件传入的slot标签的内容，存放在vm.$slot中，默认插槽为vm.$slot.default，具名插槽为vm.$slot.xxx，xxx 为插槽名，当组件执行渲染函数时候，遇到slot标签，使用$slot中的内容进行替换，此时可以为插槽传递数据，若存在数据，则可称该插槽为作用域插槽。

对keep-alive的理解，它是如何实现的，具体缓存的是什么？ ​

keep-alive是Vue.js内置组件 能够将不活动的组件实例保存在内存中 而不是直接销毁 是一个抽象组件 不会被渲染到真实的DOM 中 也不会出现在父组件链中

  • include 字符串或正则表达式，只有名称匹配的组件会被匹配； -exclude字符串或正则表达式，任何名称匹配的组件都不会被缓存；
  • max 数字，最多可以缓存多少组件实例。

2 个生命周期 activated ， deactivated

  • activated：组件被激活时调用；
  • deactivated：组件被停用时调用。

keep-alive内部其实是一个函数式组件，没有template标签。在render中通过获取组件的name和include、exclude进行匹配。匹配不成功，则不需要进行缓存，直接返回该组件的vnode。

匹配成功就进行缓存，获取组件的key在cache中进行查找，如果存在，则将他原来位置上的 key 给移除，同时将这个组件的 key 放到数组最后面（LRU）也就实现了max功能。

$nextTick 原理及作用 ​

nextTick 其本质是JavaScript 执行原理 EventLoop 中的一种应用 nextTic k是将回调函数放到一个异步队列中，保证在异步更新DOM的watcher后面，从而获取到更新后的DOM。

因为在created()钩子函数中，页面的DOM还未渲染，这时候也没办法操作 DOM，所以，此时如果想要操作DOM，必须将操作的代码放在 nextTick()的回调函数中。

Vuex 的原理 ​

Vuex是专门为Vue设计的状态管理，当Vue从store中读取数据后，数据发生改变，组件中的数据也会发生变化

  • Vue Components 负责接收用户操作交互行为，执行dispatch触发对应的action进行回应
  • dispatch唯一能执行action的方法
  • action用来接收components的交互行为，包含异步同步操作
  • commit对mutation进行提交，唯一能执行mutation的方法
  • mutation唯一可以修改state状态的方法 - state页面状态管理容器，用于存储状态 - getters读取state方法

Vuex中action和mutation的区别 ​

  • mutation更专注于修改state，必须是同步执行。
  • action提交的是mutation，而不是直接更新数据，可以是异步的，如业务代码，异步请求。
  • action可以包含多个mutation

Vuex 和 localStorage 的区别 ​

  • Vuex存储在内存中，页面关闭刷新就会消失。而llocalstorage存储在本地，读取内存比读取硬盘速度要快
  • Vuex应用于组件之间的传值，localstorage主要用于不同页面之间的传递
  • Vuex是响应式的，localstorage需要刷新

对虚拟DOM的理解 ​

虚拟DOM就是用JS对象来表述DOM节点，是对真实DOM的一层抽象。可以通过一些列操作使这个棵树映射到真实DOM上。

虚拟DOM就一定比真实DOM更快吗 ​

虚拟DOM不一定比真实DOM更快，而是在特定情况下可以提供更好的性能。

在复杂情况下，虚拟DOM可以比真实DOM操作更快，因为它是在内存中维护一个虚拟的DOM树，将真实DOM操作转换为对虚拟DOM的操作，然后通过diff算法找出需要更新的部分，最后只变更这部分到真实DOM就可以

而在一下简单场景下，直接操作真实DOM可能会更快，当更新操作很少或者只是局部改变时，直接操作真实DOM比操作虚拟DOM更高效

虚拟DOM的解析过程 ​

  • 首先对将要插入到文档中的 DOM 树结构进行分析，使用 js 对象将其表示出来，比如一个元素对象，包含 TagName、props 和 Children 这些属性。然后将这个 js 对象树给保存下来，最后再将 DOM 片段插入到文档中。
  • 当页面的状态发生改变，需要对页面的 DOM 的结构进行调整的时候，首先根据变更的状态，重新构建起一棵对象树，然后将这棵新的对象树和旧的对象树进行比较，记录下两棵树的的差异。
  • 最后将记录的有差异的地方应用到真正的 DOM 树中去，这样视图就更新了。

DIFF算法原理 ​

diff算法发生在视图更新阶段，当数据发生变化的时候，diff会对新旧虚拟DOM进行对比，只渲染有变化的部分。

1. 新旧节点都为文本节点 ​

  • 比较 text 内容是否一致；
  • 若不一致，直接用新文本内容替换旧节点的文本内容。

2. 新节点有子节点，旧节点无子节点 ​

  • 使用 addVnodes() 直接将新节点的子节点挂载到真实 DOM 上。

3. 新节点无子节点，旧节点有子节点 ​

  • 使用 removeVnodes() 将旧节点的所有子节点从 DOM 中移除。

4. 新旧节点都有子节点 ​

  • 调用 updateChildren() 执行 双指针 diff 算法 对比两个子节点数组，尽可能重用已有节点并高效更新。

双端 diff 算法解析（updateChildren 方法） ​

在 Vue 的虚拟 DOM 更新机制中，updateChildren 是关键方法之一，它使用 双端 diff 算法 来优化子节点的比对过程。

📌 什么是双端 diff？ ​

该算法在更新新旧节点时，会创建 四个指针：

  • oldStartIdx：旧节点的头部索引
  • oldEndIdx：旧节点的尾部索引
  • newStartIdx：新节点的头部索引
  • newEndIdx：新节点的尾部索引

每次循环会比较四种组合：

  1. 新前 vs 旧前
  2. 新后 vs 旧后
  3. 新后 vs 旧前
  4. 新前 vs 旧后
